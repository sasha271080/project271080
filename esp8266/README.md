# ESP8266 (Wemos D1 mini) — Wi-Fi панель

Скетч `esp8266_ap_dashboard.ino` — вторая половина Wi-Fi моста проекта
[`project271080`](https://github.com/sasha271080/project271080).
Первая половина живёт в прошивке STM32: `Core/Src/mc_wifi.c` (USART3 + DMA).

```
   смартфон / ПК                         моторный контроллер
   ┌──────────────┐    Wi-Fi 2.4 ГГц    ┌────────────────────────┐
   │ браузер      │◄───── TCP/80 ──────►│ ESP8266 (D1 mini)      │
   │ Serial Studio│◄───── TCP/23 ──────►│  AP 192.168.4.1        │
   └──────────────┘                      └───────┬────────────────┘
                                                 │ UART 460800 8N1
                                                 │ GPIO13 RX ← PB10
                                                 │ GPIO15 TX → PB11
                                         ┌───────▼────────────────┐
                                         │ STM32F103C8T6          │
                                         │ USART3 → JSON 10 кадр/с│
                                         └────────────────────────┘
```

## Чем отличается от `wifi_bridge_d1mini.ino`

| | `wifi_bridge_d1mini.ino` (в корне) | этот скетч |
|---|---|---|
| режим | STA (клиент домашней сети) | AP, при желании AP+STA |
| интерфейс | только «прозрачный» TCP | TCP **и** веб-панель с командами |
| буфер UART | 256 Б по умолчанию | 4096 Б |
| живость связи | нет | пинг `PG` раз в секунду |
| выдача кадра | как пришло | последний целый JSON + график в браузере |

## Схема подключения

| D1 mini | GPIO | Направление | STM32 Blue Pill |
|---|---|---|---|
| **D7** | GPIO13 | вход (RX) | **PB10** — USART3_TX |
| **D8** | GPIO15 | выход (TX) | **PB11** — USART3_RX |
| **GND** | — | общий | **GND** |
| **5V (VIN)** | — | питание | отдельный источник 5 В, ≥ 700 мА |

Обязательно:

1. **Общая земля.** Без неё линия 460800 живёт секунды.
2. **Питание только на 5V (VIN).** У D1 mini свой регулятор; сажать его на
   `3.3V` Blue Pill нельзя — там уже висит МК и USB.
3. **470 мкФ** электролит у модуля по питанию — Wi-Fi даёт броски до 300 мА.
4. **Резистор 4.7–10 кОм с D8 (GPIO15) на GND.** ESP8266 выбирает режим
   загрузки по уровню GPIO15: нужен низкий. У STM32 PB11 включена подтяжка
   вверх (`GPIO_PULLUP` в `mc_wifi.c`), и без внешнего резистора модуль может
   не стартовать, пока подключён к плате.

Уровни согласованы: STM32 выдаёт 3.3 В, ESP8266 их принимает. Делитель не нужен.

## Прошивка

1. Arduino IDE → **Файл → Настройки → Дополнительные ссылки для менеджера плат**:
   `https://arduino.esp8266.com/stable/package_esp8266com_index.json`
2. Менеджер плат → установить **esp8266 by ESP8266 Community** (проверено на 3.1.2).
3. Открыть `esp8266_ap_dashboard.ino`, плата:
   **LOLIN(WEMOS) D1 R2 & mini**, 80 MHz, Flash 4 MB, Upload Speed 921600
   (если прошивка срывается — 115200).
4. Прошить по USB. Дальше USB нужен только для обновления прошивки.

> **Про имя папки.** Arduino IDE требует, чтобы папка называлась так же, как
> `.ino`. В репозитории файл лежит в `esp8266/` — это каталог проекта.
> Скопируйте папку в `esp8266_ap_dashboard` и откройте `.ino` оттуда (IDE также
> сама предложит перенести файл в папку с правильным именем).

## Настройки в начале скетча

```cpp
static const char AP_SSID[] = "MotorCtrl";
static const char AP_PASS[] = "motor271080";   // не короче 8 символов
static const char STA_SSID[] = "";             // пусто = только точка доступа
static const char STA_PASS[] = "";
#define LINK_BAUD 460800u                      // = WIFI_BAUD в mc_wifi.h
```

Пароль точки доступа смените: через неё управляют двигателем.
Если вписать `STA_SSID`/`STA_PASS`, модуль поднимется как AP+STA — панель будет
доступна и по `192.168.4.1`, и по адресу от роутера (он виден в `/api/info`).

## Как пользоваться

1. Подать питание на STM32 и D1 mini.
2. Подключиться к Wi-Fi **MotorCtrl** (пароль `motor271080`).
3. Открыть **http://192.168.4.1/** (или `http://motor.local/`).
4. Дальше — как в PID-тюнере: `Пуск` / `Стоп`, режим защиты, обороты,
   коэффициенты, защиты, сохранение в Flash.

Панель опрашивает `/api/data` каждые 300 мс и рисует график оборотов и тока.
Жёлтый график — ток в амперах, зелёный — обороты; масштаб подписан сверху.

## HTTP-API

| Адрес | Что делает |
|---|---|
| `GET /` | веб-панель |
| `GET /api/data` | последний целый JSON-кадр от STM32 как есть (`{}`, если кадров ещё нет) |
| `GET /api/cmd?c=ON` | отправить команду в STM32 (белый список, ответ `ok` / `bad cmd`) |
| `GET /api/info` | состояние моста: IP, RSSI, кадры, пропуски, клиенты, uptime |

```bash
curl "http://192.168.4.1/api/cmd?c=RV1500"
curl "http://192.168.4.1/api/data"
```

Полный список команд — в [COMMANDS.md](COMMANDS.md).

## TCP-мост, порт 23

Прозрачный канал UART ↔ TCP: всё, что STM32 шлёт по USART3, уходит клиенту, и
наоборот. Один клиент за раз.

- **Serial Studio**, Node-RED, скрипты — подключаются к `192.168.4.1:23` напрямую;
- **`pid_tuner.py`** работает только с COM-портами (pyserial). Чтобы гонять его
  по Wi-Fi, нужен виртуальный COM с TCP-мостом (com0com + hub4com) — либо
  пользуйтесь веб-панелью, она умеет те же команды.

Мост отдаёт кадры **целиком**: если TCP-буфер полон, кадр пропускается, а не
рвётся посередине (иначе тюнер получает битый JSON). Счётчик пропусков —
`drops` в `/api/info`.

## Живость связи и TRIP_COMM

В прошивке есть защита: если включён виртуальный задатчик (`rv`, команда `RV…`),
инвертор работает, а команд нет дольше **5 с** — срабатывает `TRIP_COMM`
(`mc.c:1244`).

Поэтому панель шлёт `PG` раз в секунду, но **только пока её кто-то опрашивает**
(браузер за последние 3 с или подключён TCP-клиент). Закрыли браузер — пинги
прекращаются, и защита снова работает как задумано: motor не останется крутиться
без присмотра.

## Диагностика

`GET /api/info`:

| Поле | Смысл | Норма |
|---|---|---|
| `frames` | принято целых JSON-кадров | растёт ~10/с |
| `bad` | кадров длиннее буфера | 0 |
| `fps` | кадров в секунду | 9–10 |
| `drops` | пропущено кадров в TCP-мост | 0 при одном клиенте |
| `bridge` | есть TCP-клиент | 0/1 |
| `cmd` | отправлено команд (включая `PG`) | растёт |
| `rssi` | уровень сигнала в режиме STA | −50…−70 dBm |

Типовые причины «STM32: нет кадров»:

- STM32 выключен или не в режиме JSON — отправьте `j` (кнопка «Формат JSON»);
- перепутаны RX/TX (D7/D8) или нет общей земли;
- не совпадает скорость: `WIFI_BAUD` в `mc_wifi.h` против `LINK_BAUD`;
- мост выключен командой `WE0` — до перезагрузки STM32 телеметрии не будет;
- включены O-кадры (`o`) — это бинарный поток, JSON в нём нет.

Если линия сыпет ошибками на 460800 (растёт `bad`, кадры рвутся), уменьшите
скорость с обеих сторон: `WIFI_BAUD` в `Core/Inc/mc_wifi.h` → `230400` и
`LINK_BAUD` здесь. 7 КБ/с влезают в 230400 с двойным запасом.

## Ограничения

- нет OTA — прошивка только по USB;
- нет авторизации в панели: кто в сети, тот управляет мотором;
- панель не хранит историю — график живёт в браузере;
- O-кадры (осциллограф) через панель не показываются, только через TCP-мост.
