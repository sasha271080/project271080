# Память проекта: ESP8266-панель

Файл для человека и для ИИ, который откроет репозиторий позже. Здесь — что
сделано, **почему именно так** и где грабли. Документация по эксплуатации —
в [README.md](README.md), команды — в [COMMANDS.md](COMMANDS.md).

## 1. Контекст

`project271080` — контроллер коллекторного двигателя на STM32F103C8T6:
каскад «скорость → ток → ШИМ», энкодер, три уровня защит, конфиг во Flash,
телеметрия JSON по USB CDC и по USART3 в ESP8266.

STM32 остаётся единственным местом, где принимаются решения. ESP8266 — только
транспорт и пульт: ни ПИД, ни защит, ни хранения уставок на нём нет. Это
сознательно: моторный контроллер не должен зависеть от Wi-Fi.

Связь STM32 ↔ ESP уже была реализована в прошивке (`Core/Src/mc_wifi.c`,
`Core/Inc/mc_wifi.h`, команда `WE1/WE0`), но на стороне ESP был только
«прозрачный» мост `wifi_bridge_d1mini.ino` без панели. Этот скетч закрывает
вторую половину.

## 2. Что важно знать о линии STM32 ↔ ESP

| Параметр | Значение | Где |
|---|---|---|
| Интерфейс | USART3, 8N1, без flow control | `mc_wifi.c:61` |
| Скорость | **460 800** | `WIFI_BAUD`, `mc_wifi.h:30` |
| Пины STM32 | PB10 = TX, PB11 = RX | `mc_wifi.c:48` |
| Пины ESP | GPIO13 = RX, GPIO15 = TX (после `Serial.swap()`) | скетч |
| Период кадра | 100 мс (10 кадров/с) | `WIFI_PERIOD_US`, `mc_wifi.h:34` |
| Размер кадра | до ~712 байт | `sbuf[2][1024]`, `mc.c:501` |
| Приём команд | до 64 байт, разбор по `\n`/`\r` | `cmd_buf`, `mc_wifi.c:28` |
| Кольцо приёма | 256 байт, DMA circular | `WIFI_RX_RING` |
| Передача | DMA, буфер 1024, при занятом DMA кадр **пропускается** | `mc_wifi.c:33` |

Следствия, которые нельзя игнорировать:

1. **Эха нет.** `mc_cmd_parse()` ничего не отвечает, признак связи — только
   обновление `last_cmd_ms`.
2. **Команда без `\n` не выполнится.** Поэтому мост сам закрывает строку, если
   от TCP-клиента пришла пауза > 25 мс (`tcpIdle()`), — иначе одиночный `j`
   от `pid_tuner.py` (`ser.write(b'j')`) склеивался бы со следующей командой.
3. **Экономия буфера ESP.** На 460800 стандартные 256 байт приёма — это 5 мс.
   Отсюда `RX_BUFFER_SIZE 4096` и вычитка UART дважды за `loop()`.
4. **Пропуск кадра — норма.** Если DMA на STM32 занят, кадр не уходит; панель
   должна переживать пропуски, а не считать их аварией.

## 3. Решения в скетче и их причины

**AP, а не STA по умолчанию.** Панель нужна там, где нет роутера (верстак,
гараж). STA — опция: заполнили `STA_SSID` — поднимается AP+STA. Блокирующего
`while (WiFi.status() != WL_CONNECTED)` нет: за время ожидания буфер 460800
переполнится и STM32 начнёт терять кадры.

**TCP-мост отдаёт кадры целиком.** `bridgeFeed()` копит строку и отдаёт её
только при `availableForWrite() >= длины`. Пропущенный кадр тюнер переживёт,
разорванный посередине — нет.

**Панель не парсит телеметрию на ESP.** Хранится последний целый JSON, разбор и
график — в браузере. Меньше кода в момент приёма — меньше потерянных байт.

**Пинг `PG` только при живом потребителе.** Прошивка ставит `TRIP_COMM`, если
`rpm_virt_sw && on && нет команд 5 с` (`mc.c:1244`). Пингуем раз в секунду, но
лишь пока браузер опрашивал `/api/data` за последние 3 с или подключён TCP-клиент.
Иначе ESP превратился бы в «вечного ПК» и защита потеряла бы смысл.

**Белый список команд в `/api/cmd`.** Список повторяет `mc_cmd.c`. Цель —
не безопасность (сеть локальная), а защита от опечатки в URL, которая иначе
уехала бы в моторный контроллер.

**`accept()` вместо `available()`.** В ядре ESP8266 3.x `WiFiServer::available()`
помечен deprecated (`-Wdeprecated-declarations`). Цель — ядро 3.x; для 2.x
нужно вернуть `available()`.

**Страница в PROGMEM.** ≈20 КБ HTML/CSS/JS (20083 байта) не занимают ОЗУ;
отдаётся `send_P()`. `Cache-Control: no-store` — чтобы после перепрошивки не
показывалась старая панель.

**Устаревший кадр помечается, а не выдаётся за живой.** `/api/data` всегда
отдаёт последний целый JSON (иначе панель теряла бы значения при каждом
подвисании), но добавляет `X-Stm: ok|stale|none` и `X-Frame-Age` в мс.
Браузер по `stale` гасит цифры и перестаёт тянуть график, а в шапке пишет,
сколько секунд молчит STM32. Без этого при остановленной телеметрии панель
показывала бы «онлайн» с замороженными числами — самое опасное в UI моторного
контроллера.

## 4. Проверено

Сборка `arduino-builder`, FQBN `esp8266:esp8266:d1_mini`, ядро **3.1.2**:

```
EXIT=0, предупреждений нет
RAM   (global, static) 33664 / 80192  (41%)
IRAM                   60223 / 65536  (91%)   <- запас небольшой
Flash                  314736 / 1048576 (30%)
```

IRAM 91 % — это `ESP8266WebServer` плюс lwIP. Если добавлять функциональность
(OTA, TLS, второй сервер), первым кончится именно IRAM, а не flash.

На железе скетч **ещё не проверялся** — проверка ниже.

## 5. Чек-лист первого запуска

До подключения силовой части:

1. Подать 5 В на D1 mini, убедиться, что появилась сеть `MotorCtrl`.
2. `http://192.168.4.1/api/info` → `frames` растёт, `fps` ≈ 10, `bad` = 0.
3. `http://192.168.4.1/api/data` → валидный JSON, `rpm`, `cur` меняются.
4. Панель: цифры живые, график рисуется.
5. `OF` → `on_sw = 2`, `on = 0`; `HB` → `on_sw = 0`; `ON` → `on_sw = 1`.
6. `TE1`/`ME1`/`TL0` → соответствующие поля JSON меняются на 1/0.
7. `RV1000` → `vs = 1`, `vr = 1000`; `RP` → `vs = 0`.
8. Оставить панель открытой на 10 с при `vs = 1` и `on = 1` → `trip` остаётся 0
   (пинг работает). Закрыть браузер → через ~5 с `trip = 9` (`TRIP_COMM`).
9. `RS` → `trip = 0`.
10. TCP: подключиться к `192.168.4.1:23`, видеть поток JSON, отправить `ON\n`.

Проверка сбоев линии: смотреть `bad` и `drops` в `/api/info`. Растут — снизить
скорость до 230400 с обеих сторон.

## 6. Грабли

- **BOM в `.ino`.** Файл, сохранённый PowerShell-ом с `-Encoding UTF8`, получил
  BOM, и сборка упала: `'\ufeff' does not name a type`. Редактировать только
  редактором без BOM (git-хук не нужен, достаточно не сохранять через
  `Set-Content`).
- **Имя папки.** Arduino IDE требует, чтобы папка называлась как `.ino`.
  В репозитории файл лежит в `esp8266/`, поэтому для сборки папку копируют в
  `esp8266_ap_dashboard`.
- **GPIO15 при старте.** STM32 держит PB11 в pull-up, а ESP8266 выбирает режим
  загрузки по уровню GPIO15. Без внешнего резистора 4.7–10 кОм на GND модуль
  может не стартовать, когда линия подключена.
- **`WE0`.** Выключает мост до перезагрузки STM32 — панель замолкает, и это не
  поломка ESP.
- **`o` (O-кадры).** Бинарный поток: JSON в нём не появится, панель покажет
  «нет кадров». Вернуть формат — `j`.
- **Питание.** Только 5 В (VIN), 470 мкФ у модуля. От `3.3V` Blue Pill модуль
  не запитать.

## 7. Что осталось

- OTA-обновление прошивки ESP (`ArduinoOTA`) — сейчас только USB;
- авторизация панели: кто в сети, тот управляет мотором;
- сжатие страницы (gzip в PROGMEM) — если понадобится место под ещё одну функцию;
- проверка на железе по чек-листу раздела 5.
